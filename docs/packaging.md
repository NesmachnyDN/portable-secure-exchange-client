# Self-contained packaging

## Goal

The target deployment model is **extract and run under the current user account**. The workstation should not require a machine-wide Java installation, `JAVA_HOME` configuration, a database server or an application server.

The project uses JDK `jpackage` with `--type app-image`. Each application image contains the native launcher, the application JAR and a platform-specific Java runtime generated by the JDK packaging tool.

Because the bundled runtime contains native components, application images are built on the target operating system. The repository currently validates Windows x64 and Linux x64 images in GitHub Actions.

## Build locally

First build the production application:

```bash
mvn -DskipTests package
```

Linux:

```bash
./scripts/package-app.sh
./target/package/PortableSecureExchangeClient/bin/PortableSecureExchangeClient
```

Windows PowerShell:

```powershell
./scripts/package-app.ps1
.\target\package\PortableSecureExchangeClient\PortableSecureExchangeClient.exe
```

The launcher uses the runtime packaged inside the application image. It also enables browser auto-open; the application itself remains bound to `127.0.0.1`.

## CI proof

The packaging workflow builds separate Linux and Windows app images and starts the generated native launcher with `JAVA_HOME` cleared. It then checks the local HTTP endpoint before archiving the image as a workflow artifact.

This proves the repository's zero-install Java-runtime claim for the tested runner platforms. It does **not** claim compatibility with every Linux distribution or specialized hardened operating system; those environments require explicit validation and potentially a platform-specific runtime/build pipeline.
